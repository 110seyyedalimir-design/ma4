🔧 بستهٔ اصلاحی — نسخهٔ ۳

تغییر جدید (به درخواست خودت):
  بکاپ تلگرامی دیگر پیام قبلی را **ویرایش نمی‌کند**؛ هر بار **پیام تازه**
  می‌فرستد. برای جلوگیری از پر شدن گروه، حداکثر هر ۱۵ دقیقه یک پیام تازه
  (فقط وقتی داده‌ای عوض شده باشد).

  سه کلید تنظیم (در تب Variables ریپو — همه اختیاری‌اند):
    TGSTORE_MODE          = new (پیش‌فرض) | edit (رفتار قدیمی)
    TGSTORE_NEW_EVERY_MIN = 15   ← فاصلهٔ حداقلی دو پیام تازه (دقیقه)
    TGSTORE_DELETE_OLD    = 0    ← اگر 1 بگذاری، پیام قبلی را بعد از پیام تازه پاک می‌کند

چه کار کنم؟
۱) Actions → run در حال اجرا را Cancel کن.
۲) ریشهٔ ریپو → Add file → Upload files → این ۴ فایل را بکش (بازنویسی می‌شوند):
      tgstore.py   run_all.py   persist.py   restore_from_text.py
   → Commit changes
۳) داخل .github/workflows/ → bot-24x7.yml → مداد ✏️ → Ctrl+A → Delete →
   محتوای bot-24x7.yml این بسته را Paste → Commit changes
۴) Actions → bot-24x7 → Run workflow

در لاگ باید ببینی:
   [tgstore] 💾 بکاپ تازه در گروه فرستاده شد (پیام <شناسه>)
و در گروه، یک پیام **جدید** «🗂 داده‌های ربات» در بخش ذخیره ظاهر شود.

─────── اضافه‌شده در نسخهٔ ۴ ───────
tools.py — «فایل به لینک» ایمن شد:
  • باگ پیدا شد و رفع شد: آپلود gofile/litterbox فقط ۹۰۰ مگ اول فایل را
    می‌خواند → برای فایل بزرگ‌تر، لینکِ خراب/بریده تحویل می‌داد! حالا کل فایل
    با curl به‌صورت جریانی آپلود می‌شود (RAM اشغال نمی‌شود، فایل بریده نمی‌شود).
  • سقف واقعی هر سرویس اعمال شد: litterbox/catbox فقط ۲۰۰MB؛ بالاتر از آن فوراً
    رد می‌شود و سراغ بعدی می‌رود (قبلاً دقیقه‌ها بی‌خودی معطل می‌شد).
  • در لاگ Actions هر مرحله ثبت می‌شود ([link] ✅/❌/⤵️).

─────── اضافه‌شده در نسخهٔ ۵ ───────
bot.py — دو تغییر به درخواست خودت:
  ۱) سقف فایل: متن‌های ربات حالا «تا ۱٫۸ گیگابایت» قول می‌دهند، ولی اگر تلگرام
     فایل بزرگ‌تری را واقعاً رساند (تا مرز ~۲ گیگ تلگرام) بات دیگر رد نمی‌کند و
     پردازشش می‌کند. فقط بالاتر از ~۱٫۹۹ گیگ (که اصلاً منتقل نمی‌شود) پیام روشن می‌دهد.
  ۲) گیر کردن فشرده‌سازی حل شد: خروجی ffmpeg حالا هم‌زمان تخلیه می‌شود تا بافر
     پر نشود و قفل نکند؛ بعلاوه نگهبان ۱۸۰ ثانیه‌ای — اگر ffmpeg بی‌پاسخ ماند خودش
     متوقفش می‌کند و پیام خطای روشن برمی‌گرداند (به جای قفل ابدی).

─────── نسخهٔ ۶ — ممیزی کامل خط فشرده‌سازی ───────
bot.py — کل مسیر «کم‌حجم» از ریشه ایمن شد:
  • نگهبان گیرکردگیِ ffmpeg (نسخهٔ ۵) سر جای خود.
  • جدید: نگهبان فاز دریافت — اگر دانلود فایل ۱۰ دقیقه هیچ پیشرفتی نکند، خودش
    لغو می‌شود و پیام روشن می‌دهد (قبلاً تا ابد منتظر می‌ماند).
  • جدید: نگهبان فاز ارسال نتیجه — همین رفتار برای آپلود خروجی (۱۵ دقیقه).
  • جدید: بررسی فضای دیسک قبل از شروع؛ اگر SSD رانر جا نداشته باشد از اول رد می‌کند.
  • جدید: ffprobe موقع ساخت attributها دیگر حلقهٔ رویداد را بلاک نمی‌کند (در نخ جدا اجرا می‌شود).
  • خطای هر مرحله به‌جای قفل شدن، به کاربر نمایش داده می‌شود و فایل‌های موقت پاک می‌شوند.
